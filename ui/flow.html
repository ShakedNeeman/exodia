Concerns I would put on the table myself

These are the objections I expect, and the answer I would give. Raise them. Do not wait to be asked.

1. This looks like a lot of boxes

Concern. For a first version, Redis, OpenSearch, SQS, and a plugin worker farm feel heavy.

What I would ship first. Three things only: presigned multipart to S3, Postgres as the catalog, and one async worker after seal. Redis is a live percentage. OpenSearch can wait until facet search hurts. SQS can start as “S3 event → worker”. The boxes are the production shape, not the day-one install.

2. Why not stream the file through the API? Or use tus?

Concern. A single upload endpoint is simpler to write and to debug.

Answer. A 2 TB PUT through Spring is a second copy, a memory profile I do not want, and a scaling axis tied to the API NIC. tus is a good protocol on the wrong hop. If tus sits in front of S3, we are still the pipe. Signing a URL is a metadata operation. Uploading 256 MB is a byte operation. They should not share a process.

3. Does S3 manage the “transaction”? The video? The parts?

Concern. Easy to confuse multipart with a database transaction, or S3 with a video platform.

Answer. S3 is a blob store. A radar take, a PDF, and a movie are the same thing to it: bytes plus a key. It does not transcode, it does not play video, and it does not run BEGIN/COMMIT. Multipart is an API we drive: we start it, we upload parts, we call Complete or Abort. S3 stores the parts and, on Complete, concatenates them. If we never Complete, the parts sit there and cost money until a lifecycle rule aborts them. That is not a rollback.

4. 10,000-part limit and abandoned uploads

Concern. 8 MB parts on a 4 TB file is 524,288 parts — illegal. Incomplete multiparts leak spend.

Answer. Part size is adaptive so we stay under ~8,000 of the 10,000 cap. A 14-day AbortIncompleteMultipartUpload rule is mandatory. Resume is a protocol in Postgres, not a UI trick, so people actually finish instead of starting a second MPU.

5. Metadata after upload never happens

Concern. “Upload first, form later” is the default product instinct.

Answer. The form is never later. A 12-hour transfer that dies at 90% still needs a name, a mission, and tags. S3 object tags are capped at roughly 10 tags and 2 KB — unusable as a catalog. User metadata is committed in draft. Technical metadata is a different document and is allowed to arrive late.

6. One HTTP file ≠ one catalog row

Concern. Why not one row per blob, or zip the set at ingest?

Answer. SIGMF is one thing to a person and two objects in storage. Zip destroys range reads and doubles CPU. Grouping in the UI only means every client re-solves the same problem. asset is what people browse. asset_object is what storage holds.

7. Enrichment cannot be allowed to hide the file

Concern. “Processing failed” becoming “file missing” is how catalogs go dishonest. A closed parser list will be wrong next month.

Answer. The brief says the data is diverse and that we enrich where possible. Those two sentences forbid a closed list and forbid blocking download on a parser. Unknown is a type. partial is a type. The raw object is downloadable at uploaded.

8. Search engines are bad sources of truth

Concern. Why pay for Postgres and OpenSearch?

Answer. Faceted browse needs an inverted index. Asset state, ACLs, and size totals need a database that does not lose a write during a reindex. I have seen “Elasticsearch-only” turn a rebuild into an outage. Detail by id always hits Postgres. Facets hit OpenSearch. The index is rebuildable.

9. At-least-once workers and poison extractors

Concern. SQS can deliver twice. A 2 TB spectrogram can OOM a box and retry forever.

Answer. Extractors are idempotent. Video and radar do not share a queue. After N failures the extractor is quarantined; the asset stays uploaded. Visibility timeout matches the job, not a 30-second HTTP call.

10. Integrity, ETags, and “trust TCP”

Concern. Multipart ETags are not MD5 of the file. Treating them as a content hash is a lie.

Answer. Part checksums on the storage API (CRC64-NVME / CRC32C). Complete fails closed. A content id (SHA-256) is computed asynchronously after seal. We do not block download on the slow hash.

11. Browse as a filesystem will recreate the current mess

Concern. Users will ask for their old folders back.

Answer. We ingest the original path as a facet. We do not make POSIX the product. Tens of terabytes of /mnt/storage3/newnew_final/ is why this system exists. Navigation is collections + facets + saved views. Tags-only is too weak: tags drift, collections have owners and ACLs.

12. Cost, deletes, and restricted radar

Concern. Derivatives can silently double the estate. A hard-delete of a 4 TB take is unrecoverable. Some files cannot leave the building.

Answer. Derivatives are capped (one poster, one spectrogram, one PDF page, two image sizes). Catalog delete is a state change; storage expires later. The storage interface is the S3 API, so a restricted collection can sit on MinIO behind the same catalog.
